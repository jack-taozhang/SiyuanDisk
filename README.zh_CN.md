# NebulaDisk 网盘 · 思源笔记插件

把 [NebulaDisk](https://github.com/) 云盘搬进思源笔记。你不再需要在浏览器和笔记之间来回切换：
左侧栏就是网盘的文件树，点一下就能预览或在线编辑，还能把整个目录或某个文件**嵌进笔记正文**。

> 本插件只新增文件，**不修改思源笔记与 NebulaDisk 的任何源码**。

---

## 一、它能做什么

### ① 侧边栏直接浏览网盘文件

在思源左侧边栏新增一个 **NebulaDisk** 停靠面板：

- 多盘符切换（NebulaDisk 里配置了几个挂载，这里就有几个）
- 懒加载目录树，展开才请求，上千文件的目录也不卡
- 顶部过滤框，按名称快速定位
- 右键菜单：**新建文件夹 / 重命名 / 删除 / 下载 / 复制路径 / 复制直链 / 插入到当前文档 / 嵌入到文档**
- 展开状态会记住，刷新后回到原处
- 只读挂载会显示「只读」标记，操作前就有预期

### ② 预览与在线编辑

按文件类型自动路由到最合适的引擎，**不用你操心选哪个**：

| 文件类型 | 处理方式 | 说明 |
|---|---|---|
| 图片 / 视频 / 音频 | 浏览器原生渲染 | 零转换、零延迟；视频支持拖动进度 |
| 文本 / 代码 / 配置 | 浏览器原生 + 轻量着色 | 编码自动识别（UTF-8 → GBK → GB18030 → Big5 → UTF-16） |
| Office（docx/xlsx/pptx…） | **OnlyOffice 在线编辑** | 可直接改内容，关闭编辑器自动保存回网盘 |
| CAD（dwg/dxf） | cad-viewer | 图纸浏览器中渲染 |
| PDF / 压缩包 / 其它 | kkFileView | 服务端转换预览 |

关键点：**Office 文件走编辑模式还是只读模式，由网盘目录的写权限决定**。只读挂载上会明确显示「只读模式」，避免你白改一通存不回去。

**在浏览器中打开**：预览页签工具栏有一个「浏览器打开」按钮，右键菜单里也有。
它会**按文件类型选合适的渲染通道**，保证你看到的是**内容**而不是下载提示：

| 文件类型 | 浏览器打开用什么 | 为什么 |
|---|---|---|
| PDF / 图片 / 视频 / 音频 / 文本 | 签名直链 | 浏览器**原生就能渲染**，零转换最快 |
| Office / 压缩包 / 其它 | kkFileView 预览页 | 浏览器**没有** Office 渲染器，直接给会变成下载 |
| CAD | cad-viewer 深链 | 同上，交给专用 3D 查看器 |

> **为什么不能一律用直链？**
> 浏览器只原生渲染极少数类型（PDF / 图片 / 视频 / 音频 / 文本）。
> Office、CAD 这类专用格式**即使服务端发了 `inline` 也会下载** ——
> 因为浏览器里根本没有对应渲染器。所以必须按类型分流。

### ③ 笔记内无缝嵌入

两种嵌入方式，都通过**自定义块**实现。

> ★ **围栏语法必须用「三个分号」，不能用反引号** ★
> 思源里 ` ```nebuladisk ` 只生成**普通代码块**（`type=c`），自定义块渲染器**根本不会被触发**，
> 笔记里就会一直显示成一坨裸 JSON。正确写法是：
>
> ```text
> ;;;siyuan-nebuladisk/nebuladisk
> {"kind":"tree", ...}
> ;;;
> ```
>
> 且**围栏必须顶格** —— `;;;` 前面有任何空格或字符都不认（`[;;;siyuan-…` 会退化成普通段落）。
> 最省事的做法是**用下面的插入入口**，插件会自动用正确语法写入。

**a) 插入目录（目录浏览器）** —— 在笔记正文里放一个可交互的网盘目录

```text
;;;siyuan-nebuladisk/nebuladisk
{"kind":"tree","mount":"售前项目","path":"2026/某项目"}
;;;
```

和上面一样，默认只渲染一行说明 + 「点击预览」按钮；点了才真正去读这个目录，
然后是一个可下钻的列表：文件夹点进去逐级展开，文件点一下在页签中打开。

**b) 插入文件预览** —— 把某个文件的内容嵌进笔记

```text
;;;siyuan-nebuladisk/nebuladisk
{"kind":"file","mount":"项目设计","path":"图纸/A-01.dwg","name":"A-01.dwg"}
;;;
```

**怎么插入？** 四种入口任选：

- 编辑器里输入 `/` 唤出斜杠菜单 → 搜「网盘」
- **把右侧文件树里的文件/目录直接拖进正文**（拖到哪一块，就插到那一段后面）
- 文件树上右键 → 「嵌入到文档」/「嵌入此目录到文档」
- 预览页签工具栏 → 「嵌入到文档」按钮

> **拖拽插入怎么用？**
> 按住文件树里的条目拖到正文，目标块会亮起蓝框并提示「插入到这里」，松手即插入。
> 拖拽期间会携带一段自定义标记，所以从浏览器/编辑器拖进来的普通文本**不会**被误当成网盘文件。

> **为什么用代码块而不是挂件？**
> 挂件跑在独立 iframe 沙箱里，拿不到插件的登录态；而代码块由插件进程直接渲染，可以复用同一个网络通道。
> 另外它是**纯文本**：同步、导出 Markdown 都不会丢内容（最坏情况退化成一段可读的 JSON）。

#### 嵌入块什么时候加载？（性能策略）

嵌入块里跑的是真实的预览页面（kkFileView / OnlyOffice），都很"重"。如果一篇笔记里嵌了
十来个文件、打开笔记时全部一起加载，电脑和思源都会被拖垮。所以采用**三层按需加载**：

| 层 | 规则 | 效果 |
|---|---|---|
| 1 | 打开笔记时**一个都不加载**，只显示「点击预览」按钮 | 打开笔记时对后端的请求数为 **0** |
| 2 | 点击后才加载，**想展开几个就是几个，互不干扰** | 内存只与「你实际展开的个数」成正比 |
| 3 | 点每个块自己的「收起」立即销毁 iframe（不是隐藏），并回收 OnlyOffice 的 blob | 手动即时释放 |

所以：**嵌入块的多少，不影响打开笔记的速度** —— 打开时是 0 请求，只渲染占位按钮。
至于内存，取决于**你点开了几个**：默认不会替你自动收起任何已展开的块
（方便左右对照看文档 + 表格），看完哪个就点哪个的「收起」。

## 二、安装

### 方式 A：直接放进工作区（推荐）

把整个 `siyuan-nebuladisk` 目录复制到思源的插件目录：

```
<思源工作区>/data/plugins/siyuan-nebuladisk/
```

然后重启思源，在 **设置 → 集市 → 已下载** 里启用「NebulaDisk 网盘」。

Docker 部署的思源，插件目录在容器里对应：

```
/vol1/1000/SiyuanDisk/data/plugins/siyuan-nebuladisk/
```

复制进去后 `docker restart <思源容器名>`。

### 方式 B：打包分发

仓库里已备好打包脚本，它会**自动取构建产物**并做 4 项自检
（顶层目录名、清单一致性、产物是否为单文件、必需文件齐备）：

```bash
# 1) 先构建（★ 两条都要跑：产物写本机环 + 同步仓库 dist/）
node tools/build.js
node tools/build.js --repo

# 2) 打包 —— 产出 siyuan-nebuladisk-<plugin.json 里的 version>.zip
#    zip 内顶层是 siyuan-nebuladisk/ 目录，内含运行必需文件
```

> **为什么不能自己手写 `zip` 命令？**
> 因为极易把**源码入口**（工程根 `index.js`，约 83KB，含 `import "./src/..."`）
> 当成产物装进去 —— 思源加载会失败，而且**错误只在浏览器 console 里可见**，
> `siyuan.log` 不会有任何痕迹。打包脚本对这一点有强断言。

## 三、配置

启用插件后，点顶栏的网盘图标 → **设置**（或侧边栏工具条的「更多」→「插件设置」）。

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 网盘地址 | NebulaDisk 的访问地址 | **自动推断**（见下） |
| 用户名 | 网盘账号 | `tao_zhang` |
| 密码 | 用于自动登录，存在思源本地插件数据里 | 空 |
| 启动时自动登录 | 开启后思源启动即登录网盘 | 开 |

> **网盘地址为什么是「自动推断」？**
> 因为同一个插件会被两种环境加载：桌面端（思源装在**你本机**）和
> 服务端（思源用 Docker 装在 **NAS** 上、你用浏览器访问）。
> 写死任何 IP 都会让另一种环境连不上。
>
> 默认策略：**取当前页面的主机名 + 端口 8089**。
> 网盘和思源本来就部署在同一台机器上，所以这个推断在两种场景下都成立。
> 你仍可在设置里改成别的地址（例如走 ZeroTier 或域名）。

设置页顶部有一条**通道状态横幅**：

- 绿色 ✓ = 网络通道正常
- 黄色 ⚠ = 通道未就绪，下面会给出具体原因

点「测试连接」可以立刻验证配置是否正确，并显示登录后能看到几个盘。

## 四、网络通道：直连

这一节解释插件的核心设计，遇到「连不上 / 预览不了」时先看这里。

### 现状：直连，不需要本地通道（2026-09-30 起）

思源和 NebulaDisk 确实是两个独立服务（:6806 与 :8089，不同 origin = 跨域）。
但网盘侧已经具备直连所需的一切：

- **后端已开启 CORS**（`allow_origins=["*"]`、`allow_credentials=False`）⇒ 跨域 `fetch` 能读到响应体；
- **登录下发 Bearer token** ⇒ 会话不依赖 Cookie，`SameSite=lax` 不再是障碍；
- **预览走签名直链**（`/api/raw/...?exp=…&sig=…`）⇒ `<img>` / `<video>` / 下载链接无需 Cookie。

于是插件**直接请求网盘地址**，只多带一个 `Authorization: Bearer <token>` 头：

```
插件（思源渲染进程） ──fetch──────────────────────────► NebulaDisk :8089
                     Authorization: Bearer <token>
```

**没有本地转发服务、没有端口、没有第二个进程** —— 也就没有「网盘活着、通道却死了」这种状态。

> **★★ 旧版本的内置代理已在 2026-09-30 整体删除 ★★**
> 早期版本因为网盘没有 CORS 头，会在 `127.0.0.1:6810` 起一个小 HTTP 转发层
> （`src/proxy.js`）：替插件保管会话 Cookie、限制转发路径白名单、剥离
> `X-Frame-Options`/CSP 并改写预览 HTML 里的资源地址。
>
> 删除理由：
>   1. 直连端到端可用，代理是**纯增的失败面**（会死、会占端口、会被旧进程复用）；
>   2. 它的**启动状态**曾（错误地）被当成「通道就绪」的判据 ⇒
>      在直连明明正常时，笔记里的嵌入块却拒绝渲染，显示
>      「网盘通道未就绪：代理未启动」；
>   3. 它唯一不可替代的职责（改写预览 HTML 的资源地址）在直连下并不需要 ——
>      iframe 直接指向网盘自身，同源。
>
> 想回看实现：`git log -- src/proxy.js`。

### 仍然存在的跨域注意事项

- 会话是 `sessionStorage` 里的 **Bearer token**，不是 Cookie
  （网盘的 Cookie 是 `SameSite=lax`，跨站本来也不会带上）。
- 网盘返回的地址可能用**容器内主机名**（例如 `nebula:8088`），
  必须经 `browserReachableUrl()` 改写成配置的 `serverUrl` 才能给浏览器用。
- iframe 内容仍是跨 origin（只做展示，不读其内部 DOM）。

## 五、能力边界（请务必知悉）

诚实说明做不到的事，避免你在错误的方向上排查：

| 事项 | 现状 | 原因 |
|---|---|---|
| 笔记内嵌的内容**可编辑** | ❌ 只读浏览 | 嵌入的是视图，笔记里只存「指向哪里」这一层信息，不背负网盘状态 |
| 嵌入页面内的操作同步回笔记 | ❌ | 同上，刻意设计 |
| 目录深链（跳到网盘某目录） | ⚠️ 部分 | NebulaDisk 界面是 SPA，没有目录级深链；插件改用自绘的目录浏览器绕开 |
| 移动端 | ❌ 未适配 | 移动端没有 `addDock`，需另做 UI |
| 离线浏览 | ❌ | 必须连着网盘服务 |
| 在 iframe 里读网盘页面的 DOM | ❌ | 跨 origin，浏览器禁止 |

## 六、开发与自检

> 想了解**架构决策、每个真 Bug 的根因、踩过的环境陷阱**，
> 请看 **[DEVELOPMENT.md](DEVELOPMENT.md)**（开发技术沉淀）。本文件只讲怎么用。

```bash
# 静态检查：语法 + import 目标 + 导出符号匹配 + 清单完整性
node test/syntax.check.js

# 嵌入块解析测试
node test/embed.test.js

# 端到端集成（对着一个模拟网盘跑直连链路）
node test/e2e.test.js

# 全量（含反向注入测试）
node tools/run-all-tests.cjs
```

### 为什么静态检查不能省

这套检查是刻意模仿 NebulaDisk 项目里 `check_undefined.py` 的思路：

> **「只在调用路径上炸」的错误，靠运行是抓不到的。**

具体来说，下面这些检查都**抓不到**「import 了一个不存在的导出」：

- `node --check`（只查语法，不查名字）
- 单元测试（可能没覆盖到那个模块）
- 手动点几下（没触发那条路径就看不见）

而 `syntax.check.js` 会把每个 `import { X } from "./y.js"` 和 `y.js` 实际的导出做交叉比对，
这类错误在写代码的当下就会报出来。

## 八、常见问题

**面板一直显示「通道未就绪」**
点设置里的「测试连接」。若报「无法连接网盘服务」，检查网盘地址与端口；
若报「当前环境没有 require()」，说明需要改用 JS 代码片段方案（见第四节）。

**Office 文件打开报「打开文件时发生错误」**
OnlyOffice 编辑器**外壳**能出来、只有正文失败，说明是 OnlyOffice **服务端**拉不到文档。
这是 NebulaDisk 侧的配置问题（`NB_BASE_URL` 必须是容器视角地址），不是插件问题。
可参考 NebulaDisk 仓库的 `diagnose-oo.sh`。

**kkFileView 预览一直转圈**
首次预览需要转换（Office/压缩包/CAD 尤其慢），大文件几十秒很正常。
插件会在 6 秒后提示「首次转换较慢」。若一直不返回，检查 NebulaDisk 容器的内存占用。

**连不上 / 一直提示「未配置网盘地址」**
网盘地址填错了，或没填。设置页的「通道自检」会逐条把
「地址 → 连通性探活 → 登录与列盘」的结果摆出来，先看它。
（旧版本在这里会提示「代理未启动」—— 内置代理已删除，不再有这个概念。）

**中文文本预览乱码**
插件按 UTF-8 → GBK → GB18030 → Big5 → UTF-16 顺序回退解码。
若仍乱码，说明是其它编码，可反馈具体文件。
